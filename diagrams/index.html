🎯 Design Principles

  • Microservices with single responsibility
  • API Gateway as single entry point
  • Async messaging via RabbitMQ
  • JWT-based stateless authentication
  • Service discovery with Eureka
  • Centralized config management
  • Distributed tracing with Zipkin
  • Database per service pattern

📊 Service Ports & Databases

  • Delivery Service → :8082 → delivery_db

  • Admin Service → :8084 → admin_db
  • API Gateway → :9090 (no DB)
  • Config Server → :8889
  • Eureka → :8761

Key Workflows & Status Flow

Delivery lifecycle and event-driven processing

🔄 Delivery Status State Machine

stateDiagram-v2 [*] --> DRAFT: Customer creates draft DRAFT --> BOOKED: Finalize delivery BOOKED --> PICKED_UP: Partner picks up PICKED_UP --> IN_TRANSIT: En route IN_TRANSIT --> OUT_FOR_DELIVERY: Near destination OUT_FOR_DELIVERY --> DELIVERED: Successfully delivered BOOKED --> DELAYED: Delay reported IN_TRANSIT --> DELAYED: Delay reported DELAYED --> IN_TRANSIT: Resumed BOOKED --> FAILED: Failure IN_TRANSIT --> FAILED: Failure OUT_FOR_DELIVERY --> FAILED: Delivery failed FAILED --> RETURNED: Return to sender DELIVERED --> [*] RETURNED --> [*]

📨 Async Event Flow (Delivery → Tracking)

sequenceDiagram participant DS as Delivery Service participant RMQ as RabbitMQ participant TS as Tracking Service participant DB as tracking_db DS->>DS: updateStatus(id, PICKED_UP) DS->>DS: Save to delivery_db DS->>RMQ: publish(exchange="delivery.status")
DeliveryEvent JSON Note over RMQ: Exchange: delivery.status
Queue: tracking-service-events RMQ->>TS: @RabbitListener consume event TS->>TS: Deserialize DeliveryEvent TS->>TS: Build TrackingEvent entity TS->>DB: Save TrackingEvent TS->>RMQ: ACK (message removed) Note over DS,TS: Fallback: If RabbitMQ down → sync REST call via Feign

📝 Delivery Creation Wizard Flow

sequenceDiagram participant C as Customer participant GW as Gateway :9090 participant DS as Delivery :8082 C->>GW: POST /gateway/deliveries/draft GW->>GW: Validate JWT GW->>DS: Create Draft (status=DRAFT) DS-->>C: {id: 123, status: DRAFT} C->>GW: PUT /gateway/deliveries/123/sender GW->>DS: Update sender address DS-->>C: Updated delivery C->>GW: PUT /gateway/deliveries/123/receiver GW->>DS: Update receiver address DS-->>C: Updated delivery C->>GW: PUT /gateway/deliveries/123/package GW->>DS: Update package details DS-->>C: Updated delivery C->>GW: PUT /gateway/deliveries/123/finalize GW->>DS: Validate all fields → BOOKED DS->>DS: Calculate charge DS->>DS: Publish event to RabbitMQ DS-->>C: {id: 123, status: BOOKED, charge: 13.99}
